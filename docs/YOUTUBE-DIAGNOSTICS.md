# YouTube converter: pipeline, diagnostics and root-cause analysis (1.5.2)

Full build only. Video Grabber converts YouTube media **only when the page already exposes directly
fetchable, unencrypted track URLs**. It never runs or reimplements YouTube's signature code, never
generates proof-of-origin (PO) tokens, never transforms the `n` parameter, never unwraps UMP/SABR
responses and never touches DRM. When YouTube does not expose such URLs, the converter cannot work, and
the YouTube tab says exactly why.

## Pipeline stages

| # | Stage | Where | What can fail |
|---|---|---|---|
| 1 | Detecting media | popup → service worker | Page scan blocked; no `googlevideo.com` requests observed |
| 2 | Retrieving metadata | page main world (read-only) | No player response for the current video id; playability not OK; DRM |
| 3 | Discovering tracks | service worker | Formats listed without URLs (UMP/SABR), ciphered formats, expired URLs |
| 4 | Connecting to media server | download tab | HTTP 403/404/410, HTML instead of media, server ignores byte ranges |
| 5 | Downloading video | download tab | Throttling, stalls (30 s without data), HTTP errors mid-download |
| 6 | Downloading audio | download tab | Same as stage 5 |
| 7 | Merging or converting | FFmpeg WebAssembly worker | WASM load failure, empty input, codec error, out of memory |
| 8 | Saving completed file | download tab + service worker | Output validation, interrupted save, saved size mismatch |

Stages 1–3 run every time the YouTube tab refreshes (every 2 s while open). Stages 4–8 run in the
"YouTube download" tab, which shows each stage with its duration and result. The popup shows
`Stage N/8 · …` while a job runs and `Last job failed at stage N/8 · …` afterwards.

## Diagnostics panel

The YouTube tab's **Diagnostics** section (and the download tab's) shows a JSON report; **Copy
diagnostics** copies it. Contents:

- **detection** — page scan result, player count, page resources, observed `googlevideo` requests,
  UMP/SABR request count, failed responses; metadata source (`movie_player`, `ytInitialPlayerResponse`,
  …), playability status, number of formats with a direct URL / ciphered / without URL, server-ABR flag;
  usable video/audio tracks, expired tracks, the configuration category and its explanation, and the
  track list (itag, quality, MIME, codecs, size, language, expired).
- **job** — status, current stage and per-stage results with durations, selected video/audio formats
  (itag, quality, MIME, codecs, size), conversion plan (e.g. `copy video · encode AAC audio`), the last
  40 HTTP requests (kind, status code, time, content type), bytes downloaded, total, speed, last
  successful operation, throttling warning, actual error, the last FFmpeg log lines and the verified
  output (bytes, tracks, MP3 bitrate, saved size).

**Privacy:** the report never contains the page URL, cookies, or URL query values other than `itag`,
`mime`, `clen`, `dur`, `gir`, `keepalive`, `aitags` and `source`. Signatures (`sig`, `lsig`), tokens
(`pot`), `n`, `expire`, IP addresses, client and session parameters are removed before anything is
stored or displayed.

## Configuration categories (stage 3)

| `configuration` | Meaning | Can Video Grabber download it? |
|---|---|---|
| `direct` | Track URLs that are fetched with plain GET byte ranges were found | Yes (stages 4–8 still decide) |
| `sabr` | YouTube streams this video with UMP/SABR (server-driven POST requests), or lists formats without any URL | No – proprietary streaming protocol |
| `ciphered` | Format URLs require signature deciphering | No – requires YouTube's player code |
| `drm` | Licensed content with DRM | No |
| `login-required` | Sign-in / age / content confirmation required | No – not bypassed |
| `unplayable`, `upcoming` | No playable media | No |
| `expired` | Previously detected URLs expired (≈6 h) | Replay the video and Refresh |
| `live-hls` | Live stream with a normal HLS manifest | Yes – via the Media Scanner tab |
| `none` | Nothing observed yet | Play the video, then Refresh |

## Typical stage-4/5 errors

| Symptom in diagnostics | Meaning |
|---|---|
| `connect` failed, `lastStatus: 403` | YouTube refused the URL. Current YouTube playback usually requires a PO token and/or a transformed `n` parameter generated by YouTube's player; Video Grabber does not generate or bypass these. An expired URL can also return 403 – replay and Refresh to tell them apart. |
| `connect` failed, 404/410 | URL expired. Replay the video and Refresh. |
| `warning: … sending the … stream slowly` | YouTube throttles URLs used outside its player. The download continues and completes, slowly. |
| `The … server ignored the requested byte range` | The URL is not a range-capable track URL (e.g. UMP); not supported. |
| `convert` failed | FFmpeg error text and log lines are included; out-of-memory is reported explicitly. |

## Root-cause analysis (1.5.2)

**What was verified.** A local YouTube simulation (`scripts/test-youtube-e2e.cjs`) maps
`www.youtube.com` and `*.googlevideo.com` to a local HTTPS server inside real Chromium 141 with the
built extension. With directly fetchable track URLs the complete pipeline works: detection, popup quality
list, download tab, byte-range transfer, FFmpeg WebAssembly, saving and verification — MP4 from
H.264+AAC and from VP9+Opus, MP3 at 128/192/320 kbps (bitrate verified by ffprobe), files decode cleanly.
403, UMP/SABR-only and ciphered configurations produce the expected stage and explanation, and a
throttled (~8 KB/s) stream shows continuous progress and completes.

**Defects found and fixed in the extension.**

1. *VP9/AV1-only qualities converted for a very long time:* WebM (VP9) video was re-encoded to H.264 in
   single-threaded WebAssembly. Measured: 10 s of 1080p30 VP9 took 43.6 s (≈4.4× slower than real
   time, so a 10-minute video stays on "Converting" for over 40 minutes). Now H.264, VP9 and AV1 video
   is copied into MP4 (1.1 s for the same input) and AAC audio is copied; only Opus/Vorbis audio is
   encoded to AAC.
2. *No stage visibility:* failures appeared as a generic "loading" state. Each stage now reports
   progress, duration, HTTP status and the actual error, and the stage name is shown in the popup.
3. *Formats without URLs* (a UMP/SABR-only player response without `serverAbrStreamingUrl`) were reported
   as "no tracks detected" instead of UMP/SABR. Now classified as `sabr`.
4. *Success checks:* MP3 output is now verified by reading its frame header (bitrate must match the
   request); the service worker re-checks the saved download (exists, complete, non-empty, size equals
   the validated output) before accepting "complete".
5. *1.5.1 fixes kept:* idle timeout instead of a total timeout, continuous transfer progress.

**What could not be verified here, and the likely real-world cause.** Real YouTube was not reachable
from the development environment, so the behavior of today's YouTube against the extension is
**not** verified. Based on how YouTube currently serves media, the most likely real-world failure
points are outside the extension's control:

- **Stage 3, `sabr`** – the web player streams through UMP/SABR (POST requests with a proprietary
  container). There are no track URLs to download; this is the most common case.
- **Stage 3, `ciphered`** – formats require signature deciphering.
- **Stage 4, HTTP 403** – direct URLs exist but YouTube requires a PO token or transformed `n` parameter.
- **Stage 5, throttling** – URLs work but are slowed to tens of KB/s.

Supporting those would require reimplementing or executing YouTube's protection mechanisms (signature
and `n` transforms, BotGuard/PO tokens, SABR client), which this project deliberately does not do. Run
the converter on the failing video, open **Diagnostics → Copy diagnostics**, and the `stage`,
`configuration` and `lastStatus` fields show which of these applies.
